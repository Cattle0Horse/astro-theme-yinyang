# 实现规范

## 分层与依赖

| 位置 | 职责 |
| --- | --- |
| `src/routes/`、`src/layouts/` | Astro 路由入口、布局、SEO 与静态输出。路由由 `src/integration.ts` 注册，调用共用内容查询和 URL 逻辑。 |
| `src/content/`、`src/collections.ts` | Markdown 源文、集合入口规则与 schema。Posts 和 Notes 各自定义字段，通过 schema 推导数据类型。演示站和模板的 `src/content.config.ts` 加载同一组集合。 |
| `src/components/` | 用 Astro 输出静态视图。需要浏览器状态的部分用 React 和 TypeScript，按功能划分 island。 |
| `src/lib/` | 内容、路径、Markdown 转换及浏览器辅助逻辑。文件系统和构建依赖留在构建端。 |
| `src/styles/` | Tailwind 入口、公共设计变量和 Markdown 等局部样式。规则见 [设计系统](../DESIGN_SYSTEM.md)。 |

- 配置 `output: 'static'`，动态路径在构建时枚举。HTML、RSS、可选 Markdown 原文和 404 随静态资源一起输出到 `dist/`。新增依赖须适配这个部署模式。
- TypeScript 使用 Astro 的 `strict` 配置。优先从 schema 和现有类型推导。front matter、配置、DOM 和浏览器存储的数据在进入业务逻辑前校验，组件接收已规范化的值。
- JSX 用于 React 组件，页面入口与静态内容用 `.astro`。先用静态 HTML、原生控件和 CSS 完成基础行为，再按需 hydrate。客户端组件只接收所需数据。状态就近管理，事件处理器表达用户操作，effects 负责外部订阅并在卸载时清理。
- 采用 Astro 提供的静态路由和导航能力。浏览器提供普通链接、锚点和滚动的基础行为。客户端路由的补充逻辑按已验证的体验需求增加，覆盖首次访问、前进后退和快速换页。
- `entry-transition.ts` 协调查找目标页和换页生命周期，`entry-motion.ts` 管理快照和动画。阅读锚点与 Astro 历史状态由 `reading-history.ts` 同步，滚动动画由 `reading-scroll.ts` 管理。历史遍历中断滚动时，会保留离开前最后一次滚动位置。

## 内容与发布

- 内容入口和字段见 [写作说明](../README.md#写作)以及 `src/collections.ts`。纯日期保留原始日历日期，带时区的时间戳按站点时区显示和分组。
- Posts 和 Notes 的详情分别使用 `/posts/<slug>/` 和 `/notes/YYYY-MM/NNN/`。Blog 和 Notes 分别在 `/index.xml` 和 `/notes/index.xml` 提供 RSS。
- 附件发布限于已发表条目引用、且位于条目目录内的非 Markdown 文件。附件以详情 URL 为基准发布，嵌入列表的 Note 也以其详情 URL 解析相对资源。
- Markdown 在构建期通过 remark 和 rehype 转换，Shiki 负责代码高亮，KaTeX 负责公式渲染。一个页面嵌入多条 Note 时，正文 ID 和同页引用按条目限定。
- Markdown 保留作者输入的引号、连字符和省略点。Unified 处理器关闭 SmartyPants 的自动标点转换。
- 公开页面、文件和 feed 共用发布筛选及 URL 生成。草稿从所有公开输出中排除。保留已发布 URL、标题锚点和 RSS 条目标识，根路径和子路径使用同一套路径规则。改动这些约定时，用现有站点产物核对兼容性。
- 静态构建按集合复用已排序的公开条目。Notes 和 Notes 标签的第一页由列表根路径渲染，旧的 `/page/1/` 路径输出静态跳转页。
- 启用 `originalMarkdown` 时，详情路径下的 `index.md` 保留原文件及 front matter。点击复制时读取同路径下的 `body.md`。普通链接、章节锚点和基础阅读在关闭 JavaScript 时可用。
- 构建时输出目录、代码、表格和块级公式控件，并标记脚注回跳的分句起点。公式复制使用 KaTeX 的 `application/x-tex` 注释作为源文。浏览器绑定控件事件、定位当前章节，并用实际排版范围绘制旁注和脚注的圈选。旁注布局与代码折叠初始化仅随对应内容输出。
- `ArticleToc.astro` 输出静态目录，由同级脚本管理定位、弹窗和焦点。正文增强通过 `reading-features.ts` 按条目挂载，并在 Astro 换页后清理失效的条目。旁注、代码折叠和图片重试按需内联构建后的脚本，使外部脚本延迟或失败时仍可用。公式选区脚本仅随含公式的页面加载。
- Markdown 渲染记录是否生成了 KaTeX。详情页和 Notes 列表将公式标记交给布局，布局按需在页头链接 KaTeX 样式。正文样式和 KaTeX 字体随静态构建发布，站内导航在换页前加载目标页的样式。
- 缓存条目缺少公式标记时，使用其已渲染的 HTML 判断是否需要 KaTeX。开发服务器以 CSS 响应提供 KaTeX 样式链接。

### 正文旁注

`remarkSidenotes` 将编号选区和对应的多行注释配对。每个编号需要一组起止标记和一份非空定义，配对失败时保留正文并报告位置。重叠选区的文本片段可以关联多个编号。每条旁注只渲染一份正文，静态输出使用 `details` 和 `summary`。旁注标题独立于文章目录。

正文和旁注共享条目末尾的脚注列表和编号。每个 `[^id]` 在所属条目中定义一次，正文和任一旁注都可引用。写法见 [阅读示例](../src/content/posts/reading/markdown/index.md)，交互见 [旁注与脚注定位](../DESIGN_SYSTEM.md#旁注与脚注定位)。

## 主题包与站点模板

`astro-theme-yinyang` 提供 integration 和集合定义。主题仓库的演示站和 `starter/` 共用这两处入口。创建站点和安装主题依赖都使用 GitHub 的 `main` 分支。运行 `pnpm update astro-theme-yinyang` 时，pnpm 将锁文件更新到分支的最新提交。`package.json` 的 `files` 声明主题包所需源码。分发验证覆盖从无标签的 `main` 安装、子路径构建以及更新主题后的用户文件完整性。

## 互动 404

Astro 页面输出缺页提示和返回链接。客户端 React 岛按设备和配置选择一个场景，再动态导入对应组件。场景组件管理内容、状态和事件，动画和拖拽通过 SVG 引用和浏览器 API 实现。场景加载或渲染失败时，静态提示继续可用。

## 外观偏好

主题在所有系统设置下使用统一的动效。CSS、客户端脚本和构建产物不通过 `prefers-reduced-motion` 切换动画、过渡或滚动行为。

明暗、配色和字号各自选择，统一由 TypeScript 偏好模块解析、校验和应用。字号仅接受 14–18 的整数档位，无有效值时使用 15。直达时在首绘前应用偏好，页头控件由原生事件处理脚本接管。采用 `ClientRouter` 时，通过 `astro:before-swap` 将当前有效偏好同步到目标文档根元素，换页首帧延续当前外观。

存储读取失败时从默认值初始化。存储写入失败时，当次选择立即应用并保留在内存中，可在当前客户端导航会话内继续使用。没有 JavaScript 时页面使用静态默认外观。

长文预览字号时，远离视口的段落保留当前块尺寸，由浏览器按需排版。字号落档后分帧恢复这些段落的常规排版。

画布配色与偏好初始化放在页面头部，早于外部样式。正文首绘使用字体回退，外部字体加载后在下一次明暗、配色或字号切换时重新应用。

## 格式与诊断

- 本仓库的格式基线为 2 空格缩进、LF、`printWidth: 188`、无分号、无尾逗号，保留 `package.json` 键顺序。Oxfmt 与 Astro 官方 Prettier 插件分别检查源码和 `.astro` 模板，沿用相同风格。
- `.oxlintrc.json` 使用 `@stylistic/eslint-plugin` 检查声明前后及类方法之间的空行。批量格式化排除构建产物、锁文件和 Markdown 内容。
- 本地及 CI 共用 `package.json` 中的检查命令。格式化、Oxlint、`astro check` 和静态构建分别核对格式、源码规则、类型和发布产物。

## 验收

| 改动 | 验证结果 |
| --- | --- |
| 内容、Markdown 或路由 | 检查构建产物中的页面、锚点和相对资源。发布逻辑改动覆盖非文章 Markdown、草稿及其独有附件、标签、两条 RSS 和原文输出。 |
| 布局或样式 | 用同一批内容比较桌面和手机的实际页面，同时检查明暗、长标题、宽内容及字体加载后的布局。 |
| 交互或导航 | 用浏览器验证相关键盘和触屏路径、焦点与状态。导航改动覆盖直达、换页、历史恢复和无脚本阅读。 |
| 构建或部署 | 用普通静态文件服务器提供 `dist/`，检查入口、根路径和子路径资源、刷新及 404。 |

按影响范围运行检查，复用已有 fixture 和回归测试。新增测试以实际输出和用户行为为断言，例如点击原文链接后能打开正确的文件，或按下 Esc 后焦点返回触发按钮。格式、类型和静态构建由工具检查，视觉对照与交互验收使用实际浏览器。
